# Локальное окружение проекта

Окружение: Windows x64, Python 3.12.14, каталог `.venv` внутри проекта. Пакеты устанавливаются в него, а не в системный Python. Полный список установленных версий и зависимостей сохраняется в `requirements.txt`.

Заключительная проверка 28 октября 2026 года: полный проект выполнен в новых каталогах, четыре кодовые ячейки итогового notebook реально исполнены Python 3.12.14. Зависимости повторно проверены через pip check, конфликтов нет. Создание ещё одного venv и повторная загрузка пакетов при этой проверке не выполнялись. Установка в другом окружении остаётся отдельным шагом по закреплённому requirements.txt.

Установлены NumPy 2.5.4, pandas 3.1.0, SciPy 1.18.1, statsmodels 0.15.0, DuckDB 2.0.0, Plotly 7.1.0, pytest 9.1.1, JupyterLab 4.6.4 и ipykernel 7.4.0. Полный список версий — в [requirements.txt](requirements.txt).

Основные библиотеки:

| Назначение | Библиотеки |
|---|---|
| Генерация и таблицы | NumPy, pandas |
| Статистика | SciPy, statsmodels |
| SQL и Parquet | DuckDB |
| Графики и HTML | Plotly |
| Проверки | pytest |
| Исследовательские notebooks | JupyterLab, ipykernel |

## Запуск проекта

В PowerShell:

```powershell
& '.\.venv\Scripts\python.exe' -B -m src.config --config '.\config.json'
& '.\.venv\Scripts\python.exe' -B -m src.run_pipeline --run-dir '.\data\runs\my_run' --report-dir '.\outputs\my_case'
```

Команды выполняются из корня проекта. Каталоги результатов должны быть новыми. Явный путь к интерпретатору выбирает нужное окружение без активации и изменения политики выполнения PowerShell. `-B` отключает запись файлов байткода. Подробности запуска — в [README.md](README.md).

Для работы с notebooks:

```powershell
& '.\.venv\Scripts\python.exe' -m jupyterlab
```

JupyterLab установлен; при настройке окружения сервер автоматически не запускается. В редакторе нужно выбрать интерпретатор `.venv\Scripts\python.exe` из этого проекта.

## Проверка зависимостей

```powershell
& '.\.venv\Scripts\python.exe' -m pip check
& '.\.venv\Scripts\python.exe' -m pip list
```

`pip check` проверяет совместимость объявленных зависимостей. Он не заменяет тесты расчётов и полный запуск проекта.

## Восстановление окружения

После перехода в каталог проекта создай `.venv` установленным Python 3.12. Если доступен Windows launcher:

```powershell
py -3.12 -m venv '.venv'
& '.\.venv\Scripts\python.exe' -m pip install -r '.\requirements.txt'
& '.\.venv\Scripts\python.exe' -m pip check
```

Если launcher отсутствует, вместо `py -3.12` укажи полный путь к Python 3.12. Снимок зависимостей подготовлен для Windows и Python 3.12; доступность тех же пакетов на другой платформе нужно проверять отдельно. Существующее рабочее окружение пересоздавать для обычного запуска не требуется.

## Выполнение Jupyter notebook

run_pipeline автоматически запускает notebook и сохраняет фактические выводы ячеек. Клиент и ядро общаются только через 127.0.0.1. В среде с запретом локальных сокетов выполнение ядра невозможно: команда даёт явную ошибку и незавершённый manifest. Настройки брандмауэра программа не меняет.

На Windows для клиента используется локальный SelectorEventLoop, совместимый с ZeroMQ, без изменения глобальной политики событий. Служебные каталог IPython, временные файлы и runtime ядра размещаются внутри нового каталога запуска, в .notebook_runtime, и не включаются в хеши артефактов. Сетевого доступа к внешним сервисам для выполнения готовых расчётов не требуется.

Каталоги `.venv`, временные файлы установки и кэши исключены из Git через локальный `.gitignore`. Зафиксированные версии не следует обновлять автоматически во время учебного этапа: изменение окружения должно сопровождаться повторной проверкой расчётов.
