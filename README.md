# Учебный A/B-эксперимент карточки объявления

Завершённый локальный кейс на синтетических данных маркетплейса: воспроизводимый генератор, SQL-витрина, статистическое решение и интерактивный дашборд. Реальных данных или результатов Авито здесь нет.

[Открыть автономный дашборд](learning/release_case/dashboard/dashboard.html). Данные, стили и Plotly встроены в HTML; для просмотра не нужны Python, сервер или интернет.

## Содержимое репозитория

- [Протокол](protocol.md) — метрики, выборка, временное окно и правила решения.
- [Контракты данных](data_contracts.md) — схемы, ключи, дубли и цепочки событий.
- [Окружение](ENVIRONMENT.md) — установка и проверка зависимостей.
- [План и границы проекта](case_plan.md) — продуктовая задача и критерии реализации.

- `src/` — генерация, подготовка, анализ, визуализация и полный запуск.
- `sql/` — очистка, пользовательская витрина, итоговые и дневные агрегаты.
- `tests/` — проверки данных, статистики, решений и воспроизводимости.

## Быстрый старт

Среда: Windows x64, Python 3.12. Проверено в Python 3.12.14 с закреплёнными версиями [requirements.txt](requirements.txt). Выполняй команды из корня проекта.

Если окружение ещё не создано:

```powershell
py -3.12 -m venv '.venv'
& '.\.venv\Scripts\python.exe' -m pip install -r '.\requirements.txt'
& '.\.venv\Scripts\python.exe' -m pip check
```

Если launcher `py` отсутствует, укажи полный путь к установленному Python 3.12. Существующее рабочее окружение пересоздавать не нужно.

Весь расчёт одной командой:

```powershell
$env:PYTHONUTF8 = '1'
& '.\.venv\Scripts\python.exe' -B -m src.run_pipeline --run-dir '.\data\runs\my_run' --report-dir '.\outputs\my_case'
```

Оба пути в команде — новые локальные выходные каталоги, создаваемые программой. Они должны быть разными и не вложенными друг в друга. Готовые промежуточные данные для запуска не требуются. Существующие результаты не удаляются и не перезаписываются.

Команда выполняет генерацию четырёх сценариев, проверки и SQL, полный анализ, сборку дашборда, экспорт результатов и реальные ячейки Jupyter. Созданные локальные артефакты не входят в состав репозитория; программа выводит их расположение после завершения. Для ядра Jupyter необходима связь по 127.0.0.1. Интернет при установленном окружении не требуется.

По умолчанию используется `config.json` с seed=42. Опция `--config` выбирает другой заранее подготовленный снимок. Перебор параметров после просмотра результата не входит в методологию кейса.

## Методология

- Единица назначения и анализа — пользователь; все назначенные остаются в знаменателе (ITT).
- Ожидаемое A/B — 50/50. Набор фиксирован заранее: 14 суток; индивидуальное окно — [назначение, назначение + 24 часа). После набора сбор продолжается ещё сутки.
- Основная метрика — доля пользователей с хотя бы одним корректным контактом. Повторные действия не увеличивают число независимых наблюдений.
- Основной z-тест двусторонний, alpha=0.05; интервалы разницы — Newcombe.
- Проверяются ненулевые размеры групп, не менее 10 успехов и неуспехов в каждой группе и не менее 10 ожидаемых наблюдений в каждой ячейке при H0.
- SRM блокирует продуктовый вывод при p<0.001.
- Защита требует верхнюю границу разницы ошибок не выше 0.005.
- Положительная рекомендация дополнительно требует значимого положительного эффекта и нижней границы выше бизнес-порога 0.005. Расхождение теста и интервала относительно нуля даёт неопределённый результат.
- Плановый MDE 0.012 и бизнес-порог 0.005 имеют разные назначения. Требуемая выборка — 11 999 на вариант; плановая мощность 80% относится к нулевому эффекту при выбранной альтернативе.

Полные правила и численные расчёты находятся в протоколе. Анализ не использует известный генератору эффект для построения оценки или выбора решения.

## Архитектура

```text
config.json → generate_data → пользователи, назначения, события
                              ↓ prepare_data + sql/01–04
                         user_metrics + агрегаты
                              ↓ analyze + decision
                         полный анализ сценариев
                              ↓ dashboard + case_materials
                         локальные артефакты
```

[run_pipeline.py](src/run_pipeline.py) связывает этапы. [generate_data.py](src/generate_data.py) использует независимые потоки PCG64. [prepare_data.py](src/prepare_data.py) проверяет схемы, ключи, окна и цепочки событий. [analyze.py](src/analyze.py) оценивает наблюдаемые данные, [decision.py](src/decision.py) применяет правило протокола, [dashboard.py](src/dashboard.py) строит автономный HTML.

Точные копии событий удаляются; конфликт ключа блокирует подготовку. Контакт требует предшествующего просмотра того же объявления. Даты — UTC. Дневные доли рассчитываются из количеств по дню назначения, а не из среднего дневных конверсий.

## Поэтапный запуск

Все каталоги ниже создаются локально и должны быть новыми:

```powershell
& '.\.venv\Scripts\python.exe' -B -m src.generate_data --full --scenario all --output '.\data\raw\demo'
& '.\.venv\Scripts\python.exe' -B -m src.prepare_data --input '.\data\raw\demo' --output '.\data\processed\demo' --scenario all
& '.\.venv\Scripts\python.exe' -B -m src.analyze --full --input '.\data\processed\demo' --output '.\data\analysis\demo' --scenario all
& '.\.venv\Scripts\python.exe' -B -m src.dashboard --analysis '.\data\analysis\demo' --prepared '.\data\processed\demo' --output '.\outputs\demo_dashboard' --scenario all
```

У генератора нужно выбрать ровно один режим: `--full` или `--preview`. Preview намеренно не содержит контактов и копий, непригоден для итогового анализа и отклоняется подготовкой.

У анализа нужно выбрать `--full` или `--estimates`. Второй режим сохраняет только оценки без продуктового решения. Полнота расчёта не равна положительной рекомендации: завершённый анализ может дать отрицательный или недостоверный результат.

Проверки покрывают сохранение участников без событий, временные границы, точные копии и конфликты, SRM, применимость методов, единицы, приоритеты решений, пороги, автономность HTML и отказ перезаписи. Статус complete означает завершение всех этапов; при ошибке сохраняется незавершённый статус и причина. Хеши фиксируют конфигурацию, код, версии и созданные данные.

## Ограничения

Вероятности поведения заданы симулятором; переносимость на реальный продукт не проверена. Не моделируются взаимодействия покупателей и продавцов, выручка, качество контактов и долгосрочные эффекты. Пороги учебные и не выведены из экономики продукта.

Заданные модели +10% относительного изменения не являются достигнутым бизнес-результатом. Маленький p-value не заменяет бизнес-порог и защиту; отсутствие значимости не доказывает равенство вариантов. Опциональные A/A-прогоны, CUPED и последовательные тесты не входят в основную версию.
